# 自研车控接入米家的可行路径

调研时点 2026-11-13。回答「自研 App 的车控能力能否接入米家」。

## 结论

能接，但只有一条路，且拿不到「车」这种设备卡片。

自研端不是瓶颈：`scripts/mqtt-send.py` 已能从命令行下发全部云端车控动作，`scripts/renew.py` 实现了 refreshToken 自动续期，一次登录后 90 天内免重登。把车控封装成 HTTP 接口是整件事里最薄的一层。

瓶颈全在米家侧：官方通道对个人关闭，唯一可行的是巴法云，而它只是把车控动作伪装成开关。

## 官方通道：对个人关闭

iot.mi.com 的「个人开发者」是内测制，官方文档写明「内测名额已满，暂不对外开放」。企业通道需营业执照、企业开发者白名单账号，米家扩展程序调试还需调试版米家 App。

四种技术形态全部要求企业资质：模组直连、米家扩展程序（RN/JS，只做 UI）、云对接、Matter。

## Matter：不适用

Matter 规范的 30+ 设备类型里没有「车」——类型是规范枚举，无法自定义。米家在 Matter 中的角色是把米家设备桥出去，不是接受第三方 Matter 设备进来。

第三方虚拟 Matter 设备能否被米家配对控制，未查到可靠成功证据。

## 米家极客版：无 HTTP 能力

极客版卡片全集里没有任何网络请求类卡片，只有设备触发、变量运算、文本拼接这类。反向佐证：Oh My Sage 直连中枢网关局域网 API 暴露 32 个 MCP 工具，覆盖规则增删改、变量、日志，也没有一个能发 HTTP。

## 巴法云：唯一可行路径

个人无需资质、有免费额度。接入方式：米家 App → 我的 → 其他平台设备 → 添加 → 巴法 → 输入巴法账号，设备自动同步。

设备类型由主题名**后三位**决定。同步到米家的只有 7 类：001 插座、002 灯泡、003 风扇、004 传感器、005 空调、006 开关、009 窗帘。其余类型（010 温控器、011 热水器、012 电视、013 空气净化器）只在巴法 App 内可见，不进米家。

形态：建若干 `006` 开关主题，每个映射一个车控动作，米家里表现为若干开关卡片，小爱可直接语音控制。动作语义固定为 `on`/`off`。

状态回读可用 `004` 传感器主题：格式 `#温度#湿度#开关#`，开关位为 on/off，可承载「已上锁」这类布尔状态。

限制：没有车卡片；四跳链路 米家云 → 巴法云 → 本地服务 → 小鹏云 → 车，延迟 2–5 秒；第三方小厂无 SLA。

## 桥接服务的三个硬约束

来自 `docs/research/xpeng-app-teardown.md` 的实测记录：

1. **必须常驻**。MQTT 凭据绑定 AT 会话，AT 真实寿命约 2.5 小时；凭据的 `expireTime` 7 天是假的，AT 失效时凭据立即 `Not authorized`。
2. **凭据互废**。每次调 `createMqttAccount/app` 都会作废旧凭据，官方 App 与桥接同时用 MQTT 会反复互相挤掉。
3. **BLE 能力无法远程**。后备箱、直线召唤、启动充电依赖同处一室的蓝牙栈，无法由常驻服务代理。

## 安全边界

解锁/上锁不应经过米家链路。四跳延迟加第三方云无 SLA，撑不起解锁这一动作的安全边界。空调、闪灯、后备箱这类非安全动作适合接入。

## 被否掉的方案及原因

| 方案 | 否掉原因 |
| --- | --- |
| 米家扩展程序 / 模组直连 / 云对接 | 需企业资质，个人内测名额已满 |
| Matter 虚拟设备 | 规范无车类型；米家不作为第三方 Matter 设备的 controller |
| 米家极客版发 HTTP | 卡片全集无网络请求能力 |
| HA Xiaomi Home 反向推入米家 | 官方集成单向，只做米家 → HA，明确不支持虚拟设备 |
| 小爱自定义技能调 HTTP | 个人可注册，但触发词固定、需审核、延迟 2–4 秒 |
| Tasker/MacroDroid 监听通知 | 依赖手机常驻，可靠性最差 |

HA 若要反向，现实出口仍汇流到巴法云，不解决上述任何限制。

## 未查实

- 米家 App 里是否已有小鹏官方车控卡片。小米有「人车家全生态」战略，若小鹏已官方接入，自研桥接完全不必要。此项无确定信源，需实测。
